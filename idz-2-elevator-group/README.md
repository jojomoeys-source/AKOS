# Группа лифтов

Индивидуальное домашнее задание № 2, вариант 29.

Программа моделирует работу нескольких лифтов с общим диспетчером. Диспетчер,
каждый лифт и каждый пассажир работают в отдельных потоках `pthread`.

## Сборка и запуск

```bash
cmake -S . -B build
cmake --build build
./build/elevator
```

Пример запуска с данными из файла:

```bash
./build/elevator --config data/simple.txt --log simple.log
```

Ключ `--config` задаёт файл с исходными данными, а `--log` — файл журнала.
Справка выводится командой:

```bash
./build/elevator --help
```

Если путь к журналу не указан, используется файл `elevator.log`. Программу
можно остановить сочетанием `Ctrl+C`. Перед завершением она выводит состояния
пассажиров, которые не были доставлены.

## Входные данные

Программа последовательно читает:

1. количество этажей, лифтов и пассажиров;
2. вместимость и начальный этаж каждого лифта;
3. минимальный и максимальный интервал появления пассажиров;
4. скорость движения в этажах за такт;
5. время открытия дверей, посадки и высадки;
6. стратегию диспетчера;
7. период работы в тактах;
8. этажи отправления и назначения пассажиров.

Стратегия `1` выбирает ближайший свободный лифт. Стратегия `2` сначала ищет
попутный лифт, а затем ближайший свободный. Нулевой период работы означает,
что программа работает до доставки всех пассажиров.

Формат конфигурационного файла:

```text
этажи
лифты
пассажиры
вместимость_лифта_1 начальный_этаж_лифта_1
...
минимальный_интервал максимальный_интервал
скорость
время_открытия_дверей
время_посадки
время_высадки
стратегия
период_работы
этаж_отправления_1 этаж_назначения_1
...
```

Время появления накапливается из случайных интервалов заданного диапазона.
Если границы диапазона равны, сценарий получается воспроизводимым.

## Потоки

Главный поток создаёт остальных участников, меняет модельное время и ожидает
завершения каждого такта.

Поток пассажира ждёт своего времени появления, меняет состояние пассажира и
помещает вызов в очередь. После регистрации вызова он работает до доставки
пассажира или до общей остановки программы.

Поток диспетчера получает вызовы из очереди и выбирает лифт по заданной
стратегии. Если свободного лифта нет, вызов после следующего такта снова
помещается в очередь.

Для каждого лифта создаётся отдельный поток. Он обрабатывает движение, двери,
посадку, высадку и выбор следующей остановки. После такта лифт сообщает
главному потоку о завершении работы.

## Синхронизация

Состояния пассажиров и лифтов защищены общим мьютексом `modelMutex`. Очередь
вызовов имеет отдельный мьютекс. Количество доступных вызовов хранится в
POSIX-семафоре, на котором ожидает диспетчер.

Условная переменная `clockCondition` используется для ожидания нового такта.
Счётчик `completedLiftCount` и `liftTickCondition` образуют барьер: главный
поток не начинает следующий такт, пока не закончат все лифты. Вывод в терминал
и файл защищён отдельным мьютексом журнала.

При завершении устанавливается общий флаг остановки. Ожидающие потоки
пробуждаются, после чего главный поток вызывает `pthread_join` и освобождает
мьютексы, условные переменные и семафор.

## Работа модели

Открытие дверей, посадка и высадка занимают заданное число тактов. Лифт не
движется с открытыми дверями и не принимает пассажиров сверх вместимости.
Пассажир входит и выходит только на этаже остановки, а выходит только на своём
этаже назначения.

В журнал выводятся появление пассажира, регистрация и назначение вызова,
движение и прибытие лифта, работа дверей, посадка, высадка и доставка.

Моделирование заканчивается после доставки всех пассажиров, окончания периода
работы или получения `SIGINT`. Между модельными тактами используется небольшая
задержка, поэтому программа не выполняет пустой цикл с максимальной загрузкой
процессора.

## Тестирование

```bash
ctest --test-dir build --output-on-failure
```

В CTest добавлено девять сценариев:

- простой маршрут;
- вместимость, равная одному;
- противоположные направления;
- несколько пассажиров на одном этаже;
- разные начальные этажи лифтов;
- большое число пассажиров;
- одновременная регистрация вызовов;
- повторная обработка вызовов при занятом лифте;
- завершение по периоду работы.

Каждый тест имеет таймаут. Повторная проверка многопоточных сценариев:

```bash
ctest --test-dir build \
  -R 'simultaneous_calls|dispatcher_retry' \
  --repeat until-fail:20 \
  --output-on-failure
```

Остановка по `Ctrl+C` проверяется отдельно:

```bash
./build/elevator \
  --config data/interrupt-test.txt \
  --log interrupt.log
```

## Структура программы

```text
main                 запуск программы и освобождение исходных данных
input                чтение и проверка входных параметров
simulation           создание потоков и управление модельным временем
context              общие данные и синхронизация тактов
call_queue           защищённая очередь вызовов и семафор
person_thread        работа потока пассажира
dispatcher_thread    работа потока диспетчера
lift_thread          работа потока лифта
dispatcher           выбор подходящего лифта
actions              завершение действий с таймерами
service              двери, посадка и высадка
route                выбор следующей остановки
lift                 состояние и движение лифта
person               состояние пассажира
logger               вывод событий в терминал и журнал
statistics           итоговая статистика
interruption         обработка SIGINT
```

Для журнала используются POSIX-вызовы `open`, `vdprintf` и `close`.
