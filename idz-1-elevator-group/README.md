# Группа лифтов

Модель группы лифтов для варианта 29.
Диспетчер, лифты и пассажиры представлены отдельными объектами программы.

## Сборка и запуск

```bash
cmake -S . -B build
cmake --build build
./build/elevator
```

Запуск с данными из файла и отдельным журналом:

```bash
./build/elevator --config data/simple.txt --log simple.log
```

Справка: `./build/elevator --help`. По умолчанию журнал записывается в
`elevator.log`. Нажатие Ctrl+C корректно останавливает моделирование и выводит
состояния недоставленных пассажиров.

## Входные параметры

Программа последовательно читает:

1. количество этажей, лифтов и пассажиров;
2. вместимость и начальный этаж каждого лифта;
3. минимальный и максимальный случайный интервал появления пассажиров;
4. скорость лифта в этажах за такт;
5. время открытия дверей, посадки одного пассажира и высадки одного пассажира;
6. стратегию диспетчера: `1` — только ближайший свободный лифт,
   `2` — сначала попутный, затем ближайший свободный;
7. период работы в тактах (`0` — до доставки всех пассажиров);
8. этаж отправления и назначения каждого пассажира.

Время появления каждого пассажира формируется как сумма случайных интервалов
из заданного диапазона.

Формат конфигурационного файла:

```text
этажи
лифты
пассажиры
вместимость_лифта_1 начальный_этаж_лифта_1
...
минимальный_интервал максимальный_интервал
скорость_этажей_за_такт
время_открытия_дверей
время_посадки
время_высадки
стратегия
период_работы
этаж_отправления_1 этаж_назначения_1
...
```

## Модель времени и события

Один проход цикла соответствует одному модельному такту. Скорость определяет,
сколько этажей лифт может пройти за такт. Открытие дверей, посадка и высадка
имеют собственные таймеры. Пока выполняется одна из этих операций, лифт не
движется. Посадка и высадка выполняются только при открытых дверях.

Вывод содержит появление пассажира, регистрацию и назначение вызова, начало
движения, прибытие, начало и окончание открытия дверей, посадку, высадку,
доставку и закрытие дверей.

Моделирование завершается после доставки всех пассажиров, после заданного
периода работы или по Ctrl+C. В последних двух случаях в статистике печатается
состояние каждой невыполненной заявки.

## Тестирование

```bash
ctest --test-dir build --output-on-failure
```

CTest печатает количество пройденных тестов. Альтернативный скрипт также
сохраняет полные результаты в `tests/results`:

```bash
./tests/run-tests.sh
```

Наборы проверяют простой маршрут, ограничение вместимости, противоположные
направления, общий этаж отправления, разные начальные положения, большое
число пассажиров и завершение по заданному периоду.

## Структура программы

```text
main           запуск, освобождение ресурсов
actions        завершение операций с модельными таймерами
config         параметры моделирования и стратегия
options        аргументы командной строки
input          ввод, проверка, генерация времени появления
simulation     цикл модельного времени
dispatcher     регистрация и назначение вызовов
route          выбор следующей остановки
service        двери, посадка и высадка
lift           состояние и движение кабин
person         состояние пассажиров
statistics     итоговая статистика
logger         терминал и журнал через файловый дескриптор
interruption   корректная обработка SIGINT
```

Для журнала используются POSIX-вызовы `open`, `vdprintf` и `close`.
