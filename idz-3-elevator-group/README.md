# Группа лифтов

Индивидуальное домашнее задание № 3, вариант 29.

Программа моделирует работу группы лифтов с общим диспетчером. Основной режим
запускает диспетчер, каждый лифт и каждого пассажира в отдельных дочерних
процессах. Для обмена данными используются POSIX shared memory и семафоры.
Есть также режим независимого запуска процессов.

## Сборка и запуск

```bash
cmake -S . -B build
cmake --build build
./build/elevator
```

Пример запуска с данными из файла:

```bash
./build/elevator --config data/simple.txt --log simple.log
```

Ключ `--config` задаёт файл с исходными данными, а `--log` — файл журнала.
Справка выводится командой:

```bash
./build/elevator --help
```

Если путь к журналу не указан, используется файл `elevator.log`. Программу
можно остановить сочетанием `Ctrl+C`. Перед завершением она выводит состояния
пассажиров, которые не были доставлены.

## Независимые процессы

Сначала соберите проект и перейдите в каталог задания:

```bash
cmake -S . -B build
cmake --build build
cd build
```

Подготовьте общую память и семафоры по конфигурации:

```bash
./elevator_setup ../data/simple.txt
```

Затем запустите один диспетчер, по одному процессу на каждый лифт и пассажира.
Например, если в конфигурации один лифт и один пассажир:

```bash
./elevator_dispatcher &
./elevator_lift 0 &
./elevator_person 0 &
```

Когда все участники запущены, управляющий процесс начинает моделирование и
ожидает окончания:

```bash
./elevator_run
wait
./elevator_cleanup
```

Индексы лифтов и пассажиров начинаются с нуля. При другом количестве участников
запустите соответствующее число процессов с индексами от `0` до `N - 1`.
Участников нужно запустить до `elevator_run`. Все они записывают события в
общий `elevator.log`. Если моделирование было прервано или запуск остановился
до очистки, выполните `./elevator_cleanup` перед следующей попыткой.

Опция `--unnamed-semaphores` у `elevator` включает вариант с неименованными
семафорами в общей памяти. Для межпроцессной работы нужен Linux с поддержкой
`sem_init` и `pshared`.

## Входные данные

Программа последовательно читает:

1. количество этажей, лифтов и пассажиров;
2. вместимость и начальный этаж каждого лифта;
3. минимальный и максимальный интервал появления пассажиров;
4. скорость движения в этажах за такт;
5. время открытия дверей, посадки и высадки;
6. стратегию диспетчера;
7. период работы в тактах;
8. этажи отправления и назначения пассажиров.

Стратегия `1` выбирает ближайший свободный лифт. Стратегия `2` сначала ищет
попутный лифт, а затем ближайший свободный. Нулевой период работы означает,
что программа работает до доставки всех пассажиров.

Формат конфигурационного файла:

```text
этажи
лифты
пассажиры
вместимость_лифта_1 начальный_этаж_лифта_1
...
минимальный_интервал максимальный_интервал
скорость
время_открытия_дверей
время_посадки
время_высадки
стратегия
период_работы
этаж_отправления_1 этаж_назначения_1
...
```

Время появления накапливается из случайных интервалов заданного диапазона.
Если границы диапазона равны, сценарий получается воспроизводимым.

## Процессы

В основном режиме родительский процесс создаёт дочерние процессы: один для
диспетчера, по одному для каждого лифта и пассажира. Родительский процесс
меняет модельное время, синхронизирует такты лифтов и ожидает завершения
участников.

Процесс пассажира ждёт времени появления, меняет состояние пассажира и
помещает вызов в общую очередь. Затем он ожидает доставки пассажира или общей
остановки программы.

Процесс диспетчера получает вызовы из очереди и выбирает лифт по заданной
стратегии. Если свободного лифта нет, вызов после следующего такта снова
помещается в очередь.

Процесс каждого лифта обрабатывает движение, двери, посадку, высадку и выбор
следующей остановки. После обработки такта лифт увеличивает общий счётчик
завершивших такт лифтов.

## Синхронизация

Состояния пассажиров, лифтов и очередь вызовов находятся в POSIX shared memory.
Именованный POSIX-семафор `stateLock` защищает общие данные. Семафор
`callsAvailable` сообщает диспетчеру о вызовах в очереди. При запуске с
`--unnamed-semaphores` используются неименованные межпроцессные семафоры,
размещённые в той же общей памяти.

Счётчик `completedLiftCount` образует барьер: управляющий процесс не начинает
следующий такт, пока текущий не обработают все лифты. В независимом режиме
процессы регистрируют готовность в общей памяти, и `elevator_run` начинает
моделирование после запуска всех участников.

При завершении управляющий процесс меняет общий статус модели, будит ожидающий
диспетчер и дожидается дочерних процессов через `waitpid`. Затем удаляются
именованные семафоры и объект общей памяти.

## Работа модели

Открытие дверей, посадка и высадка занимают заданное число тактов. Лифт не
движется с открытыми дверями и не принимает пассажиров сверх вместимости.
Пассажир входит и выходит только на этаже остановки, а выходит только на своём
этаже назначения.

В журнал выводятся появление пассажира, регистрация и назначение вызова,
движение и прибытие лифта, работа дверей, посадка, высадка и доставка.

Моделирование заканчивается после доставки всех пассажиров, окончания периода
работы или получения `SIGINT`. Между модельными тактами используется небольшая
задержка, поэтому программа не выполняет пустой цикл с максимальной загрузкой
процессора.

## Тестирование

```bash
ctest --test-dir build --output-on-failure
```

В CTest добавлено девять сценариев:

- простой маршрут;
- вместимость, равная одному;
- противоположные направления;
- несколько пассажиров на одном этаже;
- разные начальные этажи лифтов;
- большое число пассажиров;
- одновременная регистрация вызовов;
- повторная обработка вызовов при занятом лифте;
- завершение по периоду работы.

Каждый тест имеет таймаут. Повторная проверка сценариев с одновременными
вызовами и занятым лифтом:

```bash
ctest --test-dir build \
  -R 'simultaneous_calls|dispatcher_retry' \
  --repeat until-fail:20 \
  --output-on-failure
```

Остановка по `Ctrl+C` проверяется отдельно:

```bash
./build/elevator \
  --config data/interrupt-test.txt \
  --log interrupt.log
```

## Структура программы

```text
main                 запуск процесса модели и освобождение ресурсов
input                чтение и проверка входных параметров
process_simulation   создание дочерних процессов и управление временем
shared_state         создание и подключение к POSIX shared memory
shared_queue         общая очередь вызовов
ipc_sync             создание и удаление POSIX-семафоров
person_process       работа процесса пассажира
dispatcher_process   работа процесса диспетчера
lift_process         работа процесса лифта
independent_*_main   точки входа отдельно запускаемых программ
dispatcher           выбор подходящего лифта
actions              завершение действий с таймерами
service              двери, посадка и высадка
route                выбор следующей остановки
lift                 состояние и движение лифта
person               состояние пассажира
logger               вывод событий в терминал и журнал
statistics           итоговая статистика
interruption         обработка SIGINT
```

Для журнала используются POSIX-вызовы `open`, `vdprintf` и `close`.
